# 최종 검증 기록

2026-10-25 로컬 Chrome 숨김 모드에서 검증했다.

- 원본 11장 × 1440/768/390px = 33개 화면을 캡처·검토했다.
- 문서 가로 넘침 없음. 1440×900 화면에서 11장 본문 모두 하단 탐색 위에 배치됨.
- 이전 버튼, 좌우 키, 노트, 전체 보기, 인쇄 시 모든 슬라이드 표시를 확인했다.
- 전달용 단일 HTML은 외부 CSS/JS 없이 3개 화면 크기에서 로드됐고 브라우저 예외가 없었다.
- PDF 페이지 객체 11개를 확인했다. PDF 자체를 별도 렌더러로 시각 검사하지는 않았다.
- 모바일의 긴 장은 세로 스크롤을 사용한다. 탐색 버튼이 본문을 덮지 않도록 문서 흐름에 배치했다.

## 자동 검사 해석
Taste Skill 검사기는 랜딩 페이지용이므로 사진 요구(few-pictures), 자동 움직임(still-page)은 사용자가 지정한 아키텍처 발표 문서에 적용하지 않았다. off-centre는 모바일 도구 모음의 폭으로 발생한 오탐이며 화면의 콘텐츠 좌우 여백은 각각 20px임을 캡처로 확인했다. 이 3개 항목을 제외한 전달용 검사에서 FAIL 0, WARN 2(no-footage, name-only-title). 표지에는 이름 바로 아래 한글 설명을 표시한다.

Impeccable detector는 큰 표지 제목의 line-height 1.03을 경고했다. 짧은 2행 표시 제목에만 적용되며 본문은 1.55다. 검사 경고를 숨기기 위한 본문 축소나 장식 이미지는 추가하지 않았다.

## 검증하지 않은 것
Oracle 연결·SQL 실행, Dify 서버 import·LLM 호출, Excel 업로드·다운로드 기능은 이 발표 HTML 제작의 검증 범위가 아니다. 결과 표는 저장소에 기록된 더미 JSON 비교 결과를 설명한다. 성능 향상 수치는 제시하지 않는다.

## 독립 검토
Impeccable의 별도 최종 검토 지침에 따라 새 문맥의 검토 Agent가 소스와 33개 화면을 검토했다. 판정: ship, 중대한 차단 결함 없음. 남은 비차단 제약은 모바일 표·주석 13px, 긴 장의 세로 스크롤, 포커스된 도구 버튼에서는 좌우 키 대신 버튼 활성화·Tab을 사용해야 하는 점이다. 스크린리더는 장 번호 변경을 안내하며 장 제목까지 자동 낭독하지 않는다.
