**아래 수동 상태 전달 절차는 변경 이력입니다.** 최신 적용은 [실행 Tool·입력 자동 구성](AUTO_INPUT_SETUP.md)을 따릅니다. COUNT/CONCAT은 01에서 실행하며, 02 Code가 session_json을 Tool에 직접 공급합니다. 요청 접수 전용 구조는 폐기했습니다.

기존 01과 등록 Tool `smart_migrate_tool`은 삭제하지 않습니다. Tool ID는 `7c7dee2e-7081-4e6a-8e63-87565b76fe89`를 유지합니다.

## 2. 02 가져오기

[02_smartmigrate_chatflow.yml](../dsl/02_smartmigrate_chatflow.yml)을 DSL로 새 앱 생성합니다. 기존 02는 정상 동작 확인까지 보관합니다.

이 버전은 상태 패킷을 따옴표·줄바꿈 없는 문자열로 감싸 `session_transport`로 출력합니다. Agent Tool의 `session_json`은 수동 문자열 변수 `{{#initialize.session_transport#}}`로 이미 연결했습니다. 다른 호환 입력은 빈 상수, request만 모델 자동 입력입니다. 이전처럼 원시 JSON을 mixed 템플릿에 끼워 넣지 않습니다. 인코딩은 JSON 전송을 위한 것으로 암호화가 아닙니다.

Agent는 최대 반복을 1로 두었습니다. Tool 호출 뒤 거대한 상태 JSON을 모델에 다시 설명시키지 않고, commit이 결과를 검증하고 별도 해설 LLM이 작은 요약을 설명합니다. 이것은 첫 호출 인자 자체의 JSON 오류를 자동 복구하는 설정은 아닙니다.

## 3. 확인할 동작

1. `매핑룰 조회해줘`: 마스터 2건·상세 10건과 이관 예상 건수가 나오는지 확인합니다.
2. `이관 진행해줘`: 부서 3건·직원 10건 처리, COUNT PASS, PK CONCAT PASS/불일치 0건이 나오는지 확인합니다.
3. `MIG_SQL과 VERIFY_SQL 결과 보여줘`: MIG_SQL·VERIFY_SQL·VERIFY2_SQL 코드 블록이 나오는지 확인합니다.
4. 같은 대화에서 다시 이관하면 중복 추가 없이 동일 건수로 처리되는지 확인합니다.

MIG_SQL은 기존 합의대로 MERGE/upsert 산출물입니다. VERIFY_SQL은 원천 조건과 대응 PK 범위의 행 수/매핑 컬럼별 비-null 건수 비교, VERIFY2_SQL은 PK 연결 후 행 CONCAT 비교를 설명하는 참고 SQL입니다. 채팅의 PASS/FAIL은 Code가 실제 JSON 데이터를 비교한 결과이며 Oracle에서 이 SQL을 실행했다는 뜻은 아닙니다. SQL의 CAST/NLS 및 자료형별 표현은 실제 DDL과 Oracle에서 검증하지 않았습니다.

## 오류가 계속되면

Tool 추론 구성의 자동 스위치는 session_json **OFF**, request **ON**입니다. session_json은 OFF로 바꾸기만 하지 말고 대화 상태 준비.session_transport 변수를 선택합니다. ON 상태는 LLM 작성 슬롯(null), OFF+빈 기본값은 빈 문자열로 전달될 수 있습니다. 정상 Agent 입력에는 session_json이 SM_STATE_V3: 문자열로 보이고 request만 null입니다.

- Agent 입력의 session_json이 빈 문자열이면 현재 연결에서 값이 전달되지 않은 것입니다. 같은 실행에서 **대화 상태 준비의 출력 탭**에 session_transport가 `SM_STATE_V3:`로 시작하는지 확인합니다. saved_state/sample_json/turn_id가 보이는 탭은 입력 탭입니다.
- 준비 노드 출력은 있는데 Agent 입력만 비면 저장된 02 DSL의 Tool parameters를 확인해야 합니다. 이번에는 최신 서버 앱의 DSL을 내보내 확인합니다. 원인 없이 모델이나 API 키를 반복 변경하지 않습니다.
- Agent에서 `Unterminated string`이 발생하면 생성된 Tool 호출 인자가 중간에 끊기거나 잘못된 JSON인 경우를 조사합니다. 원문 호출 인자/Traceback을 보기 전에는 토큰 부족·스트리밍·상태 연결 중 하나로 확정하지 않습니다. 모델 설정에서 Function Call Type은 Tool Call을 유지합니다.
