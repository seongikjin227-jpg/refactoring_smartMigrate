# 001 Sample Flow History

이 문서는 예상 사용자 요청 15개를 기준으로 `payload`가 어느 컴포넌트에서 생성되고, 어떤 key가 추가/변경되고, 어떤 output으로 분기되는지 기록한 sample history다.

## Output 종류

| 구분 | 개수 | Output |
|---|---:|---|
| 일반 챗봇 | 1 | `GENERAL_CHAT` |
| Management | 4 | `DASHBOARD`, `STATUS_CHANGE`, `CORRECT_SQL_INPUT`, `EXCEPTION` |
| Execution | 10 | 전체 작업 요청 6개, 단건/복수 작업 요청 4개 |

## 공통 Payload Shape

### 01 Request Classifier 이후

```json
{
  "component": "01_requestClassifier",
  "user_request": "...",
  "classification": {
    "route": "GENERAL_CHAT|MANAGEMENT|JOB_EXECUTION",
    "task_type": "CHAT|STATUS|JOB_EXECUTION",
    "expected_latency": "FAST|LONG",
    "needs_pending_jobs": false,
    "needs_llm_answer": true
  },
  "route": "GENERAL_CHAT|MANAGEMENT|JOB_EXECUTION",
  "expected_latency": "FAST|LONG",
  "next_node": "02_intentRouter",
  "history": [
    {
      "step": "request_classifier",
      "message": "route=..., latency=..."
    }
  ]
}
```

### 02 Intent Conditional Router 이후

```json
{
  "...": "...",
  "component": "02_intentRouter",
  "selected_output": "general_chat|management|job_execution",
  "next_node": "03_generalChatResponder|04_managementRouter|06_getPendingJobs",
  "history": [
    "...",
    {
      "step": "intent_router",
      "message": "route=..."
    }
  ]
}
```

### 04 Management LLM Router 이후

```json
{
```

### 06 Get Pending Jobs 이후

`06`은 실행 요청에서만 호출한다. CLOB/SQL 본문은 조회하지 않고 routing/status에 필요한 최소 컬럼만 조회한다.

```json
{
  "...": "...",
  "component": "06_getPendingJobs",
  "pending_jobs": {
    "migration_jobs": [],
    "sql_conversion_jobs": [],
    "sql_tuning_jobs": [],
    "sql_formatting_jobs": [],
    "job_lookup_jobs": []
  },
  "pending_summary": {
    "migration_count": 0,
    "sql_conversion_count": 0,
    "sql_tuning_count": 0,
    "sql_formatting_count": 0,
    "total_count": 0
  },
  "next_node": "08_jobExecutionRouter",
  "history": [
    "...",
    {
      "step": "get_pending_jobs",
      "message": "pending jobs loaded"
    }
  ]
}
```

### 08 Job Target Router 이후

실행 가능한 대상이면 `Data` payload로 `09 Execution Plan Summary`에 연결한다.

```json
{
  "...": "...",
  "component": "08_jobExecutionRouter",
  "job_route": "MIG|SQL_CONVERSION|SQL_TUNING|SQL_FORMATTING",
  "run_mode": "all_pending|targeted",
  "run_all_pending": true,
  "target_filter": {
    "map_ids": [],
    "sql_ids": [],
    "space_nms": []
  },
  "selected_jobs": [],
  "routing_reason": "...",
  "selected_output": "mig_job|sql_conversion_job|sql_tuning_job|sql_formatting_job",
  "next_node": "09_executionPlanSummary",
  "history": [
    "...",
    {
      "step": "job_target_route",
      "message": "job_route=..., run_mode=..., count=..."
    }
  ]
}
```

차단/실행 대상 없음이면 `Message`로 바로 Chat Output에 연결한다.

```json
{
  "component": "08_jobExecutionRouter",
  "job_route": "PREREQUISITE_BLOCKED|NO_RUNNABLE_JOB",
  "run_mode": "blocked|none",
  "target_filter": {},
  "blocked_jobs": [],
  "answer_text": "사용자에게 바로 보여줄 메시지",
  "final": true,
  "next_node": "chat_output"
}
```

```json
    }

}
```

### 요청

```text

```

### Payload History

| Step | Component | Output | Payload 변경 |
|---:|---|---|---|
| 1 | `01 Request Classifier` | `payload` | `route=JOB_EXECUTION`, `expected_latency=LONG`, `needs_pending_jobs=true` |
| 2 | `02 Intent Conditional Router` | `Job Execution` | `selected_output=job_execution`, `next_node=06_getPendingJobs` |

| 5 | `09 Execution Plan Summary` | `Notice Message` + `Payload` | 실행 예정 job 수/목록 메시지 생성, pipeline payload 생성 |
| 6 | selected Pipeline | `payload` | `pipeline_status`, `job_result.processed_jobs` 추가 |
| 7 | `13 Final Summary` | `Result Message` | 전체 실행 결과 요약 |

### 최종 연결

```text
Chat Input -> 01 -> 02.Job Execution -> 06 -> 08 -> 09 -> selected Pipeline -> 13 -> Chat Output
```


### Payload History

| Step | Component | Output | Payload 변경 |
|---:|---|---|---|
| 1 | `01 Request Classifier` | `payload` | `route=JOB_EXECUTION`, `expected_latency=LONG` |
| 2 | `06 Get Pending Jobs` | `payload` | SQL Conversion/Tuning/Formatting pending 현황 추가 |
| 3 | `08 Job Target Router` | domain target | LLM이 요청과 pending 상태를 보고 `SQL_CONVERSION`, `SQL_TUNING`, `SQL_FORMATTING` 중 하나를 선택 |

| 6 | `13 Final Summary` | `Result Message` | 최종 요약 |

### 비고

현재 구조에서 하나의 `08` output은 하나의 domain pipeline으로 연결된다. SQL Conversion, Tuning, Formatting을 모두 순차 실행하려면 multi-domain orchestration 컴포넌트를 별도로 추가해야 한다.

# Blocked / No Runnable Message 예시

이 케이스는 위 15개 output 종류에는 포함된 실행 라우터의 예외성 message output이다.

## Prerequisite Blocked

### 요청

```text
map_id=101 실행해줘
```

### 조건

```text
06 Get Pending Jobs의 job_lookup_jobs에서 map_id=101이 존재하지만 USE_YN=N 또는 STATUS != NULL로 판단되는 경우
```

### Output

```text
08 Job Target Router.Prerequisite Blocked Message -> Chat Output
```

### Message Payload

```json
{
  "component": "08_jobExecutionRouter",
  "job_route": "PREREQUISITE_BLOCKED",
  "run_mode": "blocked",
  "target_filter": {
    "map_ids": [101],
    "sql_ids": [],
    "space_nms": []
  },
  "blocked_jobs": [
    {
      "job_route": "MIG",
      "map_id": 101,
      "use_yn": "N",
      "status": "DONE",
      "runnable": false
    }
  ],
  "answer_text": "요청한 작업은 바로 실행할 수 없는 상태입니다...",
  "next_node": "chat_output",
  "final": true
}
```

## No Runnable Target

### 요청

```text
SQL Formatting 전체 진행해줘
```

### 조건

```text
06 Get Pending Jobs 결과에서 SQL_FORMATTING runnable 대상이 0건인 경우
```

### Output

```text
08 Job Target Router.No Runnable Target Message -> Chat Output
```

### Message Payload

```json
{
  "component": "08_jobExecutionRouter",
  "job_route": "NO_RUNNABLE_JOB",
  "run_mode": "none",
  "selected_jobs": [],
  "answer_text": "실행 가능한 작업 대상을 찾지 못했습니다...",
  "next_node": "chat_output",
  "final": true
}
```
