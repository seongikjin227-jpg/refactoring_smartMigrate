# 일반 응답과 예외 안내 가이드

03의 [System Prompt](../01_agent_start/03_llmResponsePrompt.md)는 기능별 설명과 사용자 요청 템플릿을 포함합니다. 일반 기능 소개는 파일 업로드/매핑, Management, 실행, Correct SQL, 유사 SQL, RAG/VectorDB를 설명합니다. 특정 질문에는 필요한 기능과 다음 행동을 자세히 안내합니다.

파일 업로드 안내는 03과 사용자 운영 가이드의 보안 제한 문구 및 Super Agent 요청 템플릿을 그대로 사용합니다. “Mig 실행 결과”처럼 짧은 요청은 최근 결과 조회로 처리하며 식별자 없이도 도메인별 최근 작업과 로그를 확인합니다. 조회 기준과 범위를 명시하고 최근 갱신 목록을 특정 실행 전체로 단정하지 않습니다.

## 예외 응답 공통 형식

1. 사용자가 원한 일과 현재 확인된 문제를 설명합니다.
2. 조회·변경·실행 중 어떤 결과를 확인했는지 밝힙니다. 미확인을 성공/실패/0건으로 단정하지 않습니다.
3. 필요한 정보를 명시하고 확인 순서를 안내합니다.
4. 사용자가 복사할 수 있는 완전한 재요청 문장 2~4개를 제공합니다. 실제 식별자를 알면 그 값을 사용하고 예시는 예시라고 표시합니다.
5. 추가 질문은 아직 모르는 도메인·식별자·목적에 집중합니다. 시스템 오류이면 요청 시각과 식별자로 운영자 점검을 안내합니다.

기술 오류는 `error`와 운영 로그에 유지합니다. 사용자 메시지는 비밀번호/API key/전체 traceback 대신 확인할 항목과 다음 행동을 제공합니다. status 변경, commit/rollback, 실제 실행 여부는 결과로 확인된 경우만 단정합니다.

## 유형별 필요한 안내

| 상황 | 설명과 다음 단계 |
|---|---|
| 번호만 지정 | Migration MAP_ID인지 SQL_SEQ인지, SQL 도메인은 무엇인지 확인. `마이그레이션 59번의 상태를 보여줘` 또는 `SQL Conversion 순번 42를 실행해줘` |
| SQL_ID만 지정 | SPACE_NM 또는 SQL_SEQ 요청. `SQL_ID S001, SPACE_NM PAYMENT의 상태를 보여줘` |
| 파일명만 지정/파싱 실패 | 보안 제한 안내와 고정 Super Agent 요청 템플릿 제공, 파일을 다시 첨부하여 재요청하도록 안내 |
| 매핑 본문 부족 | master의 MAP_ID/FR_TABLE/TO_TABLE, detail의 부모 MAP_ID/MAP_DTL/FR_COL/TO_COL 요청 |
| 실행 후보 없음 | 조회된 상태와 해당 도메인의 조건 확인. retry 0만으로 실행 가능하다고 설명하지 않음 |
| 선행 조건 불충족 | 선행 작업 상태·실패 로그 확인 후 조치. 전체 workflow 전환은 명시적인 별도 요청 |
| 조회/연결/라우팅 오류 | 결과 미확인임을 알림. 상태 조회부터 복구하고 연결·권한·전달값 점검. 바로 전체 실행 권유하지 않음 |
| 최종 집계 오류 | 집계 표시 실패와 실제 실행 결과를 구분. 현재 DB 상태·로그를 먼저 재조회 |
| Correct SQL 정보 부족 | 식별자, 저장 종류, 검토한 SQL 전문. BIND_SQL은 BIND_SET 필요. 저장 종류별 상태 전이 설명 |
| SQL/매핑 적용 실패 | Tool 결과로 확인된 commit/rollback 범위만 설명. 검증 실패 항목과 수정할 정보 안내 |
| RAG/VectorDB 오류 | DB 저장과 동기화를 구분. 저장은 완료됐지만 동기화만 실패한 경우 전체 저장을 반복하도록 안내하지 않음 |

## 구현 위치와 연결

- 02 Intent Router: 오류 Data에 `answer_text`, `exception_message`, `should_execute=false`, `final=true`를 포함합니다. clarification에도 도메인·대상·의도와 요청 예시를 포함합니다.
- 04 Management Router: LLM/파싱/상위 오류를 캐시된 EXCEPTION route로 처리합니다. 일반 관리 branch는 멈추고 Exception Message branch가 상세 안내를 반환합니다. 짧은 LLM exception_message에도 관리 요청 템플릿을 보완합니다.
- 06: 조회 오류 Data에 복구 안내와 실행 guard를 포함합니다. 오류를 정상 0건 결과로 처리하지 않습니다.
- 08: 예외 Message와 오류 Data에 상세 실행 복구 안내를 제공합니다. 대상 식별자가 있으면 그 값으로 상태 조회/실행 예시를 작성합니다. 실행 불가·선행 조건 응답에는 상태, 조건, 확인 순서가 포함됩니다.
- 04 Dashboard/Current Progress, 11 Final Dashboard, 11B Failure Cause Analyzer: 사용자에게 조회·분석·집계 실패가 의미하는 범위와 재조회 예시를 안내합니다.
- Management Agent: Tool 오류를 한 줄로 반복하지 않고 필요한 입력, 확인된 변경 결과, 복구 방법과 재요청 예시를 설명합니다.

03은 Markdown 프롬프트 문서이므로 문서 변경만으로 기존 Langflow 노드 설정이 자동 갱신되지는 않습니다. 03의 System 메시지에 새 블록 전체를 반영하고 라우터 코드를 함께 갱신합니다. 04 Router의 Exception Message와 08의 Message 출력은 Chat Output에 연결해야 합니다. Data 오류가 상위에서 반환되면 `answer_text`/`exception_message`를 보존하고 실제 실행 단계로 넘기지 않습니다.

## 응답 예시

대상 없는 요청:

> 번호만으로는 Migration과 SQL 작업 중 어느 대상을 의미하는지 확인하기 어렵습니다. 도메인과 번호, 상태 조회인지 실제 실행인지를 함께 알려주세요. 예를 들어 “마이그레이션 59번의 상태와 최근 로그를 보여줘” 또는 “SQL Conversion 순번 42를 재실행해줘”라고 요청할 수 있습니다. SQL_SEQ를 모르면 SQL_ID와 SPACE_NM을 함께 적어 주세요. 어떤 도메인의 작업을 원하시나요?

조회 오류:

> 현재 실행 대상 조회 결과를 확인하지 못했습니다. 작업이 0건이거나 이전 실행이 실패했다는 뜻은 아닙니다. 먼저 대상 번호와 도메인을 확인하고, 연결이 복구된 뒤 “마이그레이션 59번의 상태, RETRY_COUNT와 최근 로그를 보여줘”라고 재조회해 주세요. 문제가 반복되면 요청 시각과 대상 식별자를 운영자에게 전달해 DB 연결·권한·전달값을 확인해 달라고 요청해 주세요. 현재 상태를 확인한 다음 재실행 여부를 결정하는 것이 좋습니다.
