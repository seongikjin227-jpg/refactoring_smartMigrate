Super Agent의 파일 처리 기능을 활용하여 첨부파일의 내용을 조회해줘. Code Interpreter Tool은 사용하지 말고 해당 내용을 빠짐 없이 Smart Migrate 에이전트를 호출하여 전달하고 매핑룰을 등록해줘

빈 양식 생성에는 Code Interpreter를 사용합니다. 작성한 파일의 조회·등록은 수퍼 에이전트의 파일 처리 기능을 사용합니다. 매핑 등록과 실제 이관 실행은 별도 단계입니다.

1. 사전 작업과 새 프로젝트 설정값 준비

1.1 먼저 준비되어 있어야 하는 것

  • 소스 스키마 SRC_NEW: 이관할 과거 AS-IS 업무 테이블과 실제 데이터가 있어야 합니다.
  • 타겟 스키마 TGT_NEW: 이관받을 TO-BE 업무 테이블·컬럼·PK가 이미 생성되어 있어야 합니다.
  • 접속 계정은 일반적으로 타겟 계정 TGT_NEW를 사용합니다. db_username = system_schema = target_schema = TGT_NEW로 설정하고 소스 스키마 조회 권한을 부여하세요.

이 가이드는 업무 테이블을 새로 만드는 절차가 아닙니다. 제공 SQL은 SmartMigrate의 매핑·작업·로그용 관리 테이블만 생성합니다. TO-BE 업무 테이블이 있는 TGT_NEW 스키마에 관리 테이블도 함께 생성하세요. 별도 관리 계정을 사용하는 프로젝트에서만 접속 계정·관리 스키마·객체별 권한을 구분해 설정하세요.

Oracle 서비스: NEWPDB
  SRC_NEW  → 과거 업무 테이블 + AS-IS 데이터
  TGT_NEW  → 에이전트 접속 계정
             생성 완료된 TO-BE 업무 테이블 + SmartMigrate 관리 테이블

SM_NEW로 접속 → SRC_NEW 조회 → TGT_NEW로 이관·검증

대상 테이블에 데이터가 이미 있다면 이관 전 중복·초기화 방식을 DBA와 정하세요. 소스 데이터는 유지하고, 최초 실행은 TRUNC_YN=N으로 설정하세요.

5.2 정의서 작성

헤더 1~2행에만 고정 색상과 굵은 글씨를 적용합니다. TO-BE는 연한 초록색 #E2F0D9, AS-IS는 연한 파란색 #DDEBF7, 공통 식별자·설정·상세변환규칙은 연한 회색 #E7E6E6입니다. 헤더 글자는 맑은 고딕 11pt·진한 색 #1F2937·굵게로 고정합니다.

테이블매핑: A:H 초록색 · I:L 파란색 · M:O 회색. 컬럼 매핑: A:B 회색 · C:G 초록색 · H:L 파란색 · M 회색. 기존 시트·헤더·열 대응은 그대로 유지합니다.

1행 그룹만 병합합니다. 테이블매핑은 A1:H1 TO-BE / I1:L1 AS-IS / M1:O1 공통 설정, 컬럼 매핑은 A1:B1 순번 / C1:G1 TO-BE / H1:L1 AS-IS입니다. 컬럼 매핑 M1은 상세변환규칙 단일 셀로 유지합니다.

빠른 생성을 위해 헤더 영역 56개 셀에만 서식을 적용합니다. 2행 헤더와 3행 이후 입력 영역은 병합하지 않습니다. 데이터 영역 서식·테두리·드롭다운·생성 후 검사는 생략합니다.

테이블매핑, 컬럼 매핑 두 시트를 사용하세요. 1행은 그룹 제목, 2행은 헤더이며 3행부터 입력하세요.

시트작성 항목
테이블매핑A 순번→MAP_ID, D 대상 테이블→TO_TABLE, G 변환규칙→MAP_TYPE, I 원천 테이블→FR_TABLE, L 필터→CONDITION, M TRUNC여부→TRUNC_YN, N 선행 순번→PRIOR_MAP_ID
컬럼 매핑A M→MAP_ID, B D→MAP_DTL, D 대상 컬럼→TO_COL, M 상세변환규칙→FR_COL

테이블매핑 G에는 실제 변환규칙 코드를 입력하세요. 컬럼 매핑 I의 원천 컬럼명으로 M 상세변환규칙을 대체하지 마세요. 부모 MAP_ID와 상세 키 (MAP_ID, MAP_DTL)의 중복·누락을 확인하세요.
